| `/EN/deals` | 307 → 200 | 307 → 200 |

**Finding (informational, not a regression):** Production already returns 404 (never 500) for every mistyped URL tested — the RCA's "500" defect is no longer reproducible live. However, production's implementation differs from this branch's: live's response headers show `x-matched-path: /en/[...rest]` with `x-nextjs-prerender: 1` and `x-vercel-cache: HIT` — i.e. production is serving a prerendered **catch-all route** (`[...rest]`), not the `experimental.globalNotFound` mechanism this branch implements. Both approaches satisfy "never 500," but they are architecturally different, and live's page content only appears in the client hydration payload (no literal `<h1>` in the raw HTML), whereas this branch's `global-not-found.tsx` is fully static and ships literal `<h1>`/button markup in the initial response (as intended — see the file's own comment about staying static under Cache Components). This branch's approach is a genuine improvement (fully static, no PPR hole) but is not yet what's live. No action needed from QA; flagging for the record in case this surprises whoever compares before/after.

**Result: PASS** (status-code parity confirmed; implementation differs as expected since this branch hasn't shipped yet).

## Notes / accepted trade-offs (not new findings — already documented in source)

- **No-JS visitors always see German first** on the `global-not-found.tsx` page, regardless of the URL's locale (both DE/EN blocks render server-side; a client island, `NotFoundLocale.tsx`, sets `data-locale` via `useEffect` to reveal the correct block). This is a deliberate, already-reviewed trade-off (`NotFoundLocale.tsx` comment: "Accepted cost... an English visitor may see a brief German flash before this effect runs") made to keep the page fully static under Cache Components. Could not independently verify the JS-corrected behaviour with Playwright — `npx playwright` browser launch was denied by the sandbox in this environment (not retried, per instructions); curl/HTML evidence above confirms both language blocks are present and correctly wired (hrefs, copy) in the raw markup, which is what matters for the "no 500 / correct copy exists" acceptance bar.
- `/foo.bar` and `/favicon.ico` render the German-only root `app/not-found.tsx`, not `global-not-found.tsx`, per the documented routing quirk (a dotted single segment reaches `[locale]/layout.tsx` with an invalid locale and bubbles to the parent boundary). This is correct per the code's own design comment and is not locale-sensitive traffic in practice.
